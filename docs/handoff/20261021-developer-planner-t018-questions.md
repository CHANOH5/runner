# T-018 구현 중 정책 확인 3건 (관심 한도, 기록 수정 중복, 휴면 로그인)

- From: developer
- To: planner
- 종류: 질문
- 관련 ID: F-013, F-015, F-004, F-001, P-RET-03, PRD 4.4·4.8·4.10
- 상태: 답변됨

## 내용

T-018(소셜 로그인·대회·참가 예정·기록 API)을 구현하면서 PRD에 없는 경우를 아래처럼 처리했다. 다르게 하려면 알려 달라. 모두 서버 한두 줄 변경이다.

1. **관심 200개가 찬 상태에서 참가 예정 추가**
   - PRD 4.8: 참가 예정에 추가하면 관심이 자동으로 켜진다. 관심은 최대 200개.
   - 지금: 참가 예정 추가는 막지 않고 관심도 켠다 (200개를 넘을 수 있음).
   - 대안: 관심만 켜지 않기 (그러면 그 대회의 N-01~N-03은 "참가 예정 접수 전" 규칙으로만 받는다).
2. **기록 수정 시 중복 확인**
   - PRD 4.4: 같은 날짜·거리·기록 확인은 "저장 전"이라고만 되어 있다.
   - 지금: 추가할 때만 409 `DUPLICATE_RECORD`로 확인하고, 수정할 때는 확인하지 않는다.
3. **휴면(`dormant`) 계정 로그인**
   - P-RET-03: 1년 미접속 계정은 휴면 처리 또는 파기 `[확인 필요]`.
   - 지금: 휴면 계정이 소셜 로그인하면 바로 `active`로 되돌리고 로그인시킨다 (안내 화면 없음).
   - 휴면 해제 안내 화면이나 본인 확인이 필요하면 알려 달라.

## 기대하는 결과물 / 답변 형식
번호별로 "지금대로" 또는 바꿀 규칙. PRD 반영 여부.

## 답변 (받는 쪽이 작성)

(planner, 2026-10-21 — PRD v1.6 반영)
1. **지금대로.** 참가 예정 추가로 관심이 자동으로 켜질 때는 200개가 차 있어도 막지 않고 켠다 (201개 이상 허용). 200개 한도는 **사용자가 하트로 직접 켤 때만** 검사하고, 개수에는 자동으로 켜진 관심도 포함한다 (`PUT /races/{id}/interest`에서 현재 개수 ≥ 200이면 422 `LIMIT_EXCEEDED`). 이유: 참가 예정이 더 강한 의사 표시이고, 참가 예정 대회가 관심 목록·N-01~N-03 판정에서 빠지면 규칙이 갈라진다. 참가 예정에도 30개 한도가 있다. PRD 4.8. **API 변경 없음** (현재 구현 확인만).
2. **바꾼다 — 수정할 때도 중복을 확인한다.** `PATCH /me/records/{id}`에서 날짜·거리·기록 중 하나라도 바뀌었고, 바뀐 결과가 **자기 자신이 아닌** 다른 기록과 같으면 409 `DUPLICATE_RECORD`(`details.existingRecordId`). `confirmDuplicate: true`로 다시 보내면 저장. 제목·구분만 바꾸면 확인하지 않는다. PRD 4.4 + 수용 기준 2개. **API 변경 있음: PATCH 요청에 `confirmDuplicate` 추가, PATCH 에러에 409 `DUPLICATE_RECORD` 추가.**
3. **안내 화면을 추가한다 (본인 확인은 지금대로 없음).** 휴면 계정이 소셜 로그인하면 지금처럼 바로 `active`로 되돌린다 (소셜 로그인 성공 = 본인 확인). 다만 앱이 **휴면 해제 안내 화면**을 1회 보여줘야 하므로 로그인 응답에 그 사실이 필요하다. 순서: 재동의(필요 시) → 휴면 해제 안내 → S-010. PRD 4.1 "휴면 해제", 6.1 4-1, 03 S-002 하위 화면, 와이어프레임 S-002 반영. P-RET-03도 구체화했다 (휴면 기본, 30일 전 안내, 휴면 중 서비스·마케팅 푸시 중단). 분리 보관 의무 등 법정 요건은 `[확인 필요]` 유지. **API 변경 있음: `POST /auth/social`의 `logged_in` 응답에 `reactivated: boolean` 추가** (이번 로그인으로 휴면이 해제됐으면 true, 한 번만). 휴면 중 푸시를 보내지 않도록 알림 대상 확정 시 `users.status = 'active'` 조건도 확인해 달라.
