## 내용

`docs/planning/05-prd-phase1.md` v1을 작성했다 (검토 대기). 기획 권한 안에서 정한 것은 문서에 반영했고, 아래는 오케스트레이터 결정 또는 외부 확인이 필요하다.

### 결정 요청
1. **Phase 1 KPI 승인 (05 문서 2장, Q-09)** — 특히 출시 조건 두 가지: ① 접수 오픈 10분 전 알림 정시 발송률 99% ② 대회 데이터 기준 목록 대비 커버리지 80%. 나머지 목표값은 `[가설]`로 출시 4주 후 조정.
2. **Phase 1 앱 내 지도 제외 → D-008 시점 (Q-08)** — 기획안: Phase 1은 지도 SDK를 쓰지 않고 [지도 앱에서 열기](네이버 지도/카카오맵/기본 지도 앱) + 공식 코스 링크로 대체. Phase 1 범위(캘린더·등록·예측)에 지도가 필수는 아니고, 지도 비용·통합 작업을 줄일 수 있다. 개발자 의견서(`20261021-developer-orchestrator-tech-decisions-d005-d008.md`)는 D-008을 Phase 1 착수 전 확정하자고 하므로 둘 중 하나를 정해 달라: (a) 기획안대로 Phase 1 지도 없음, D-008은 Phase 2 전 확정 / (b) Phase 1에 대회장 위치 지도 포함, D-008 지금 확정.
3. **대회 데이터 입력 인력 (Q-06)** — 기준 목록 약 120~200개를 출시 전에 수동 입력해야 한다 (25~50시간 [추정], tech/05). 누가 언제 할지.
4. **대회 공유 기능 Phase 1 포함 여부 (Q-07)** — 공유하려면 딥링크 도메인과 앱 미설치자용 대회 웹 페이지가 필요하다. 기획안은 Phase 1 제외. 바이럴 측면에서 마케터 의견을 들어볼 만하다.
5. **고객센터 이메일·관리자 도메인 (Q-12)** — 탈퇴·문의·주최 측 요청 창구 주소가 문서 여러 곳에 들어간다.
6. **Android Apple 로그인 (Q-03)** — 개발자 비용 답변 후 결정. 기획 기본안: Phase 1 제외.

### 외부 확인 요청 `[확인 필요]` (법률)
7. **만 14세 확인 방식 (Q-01, P-ACC-01)** — 출생연도만 받고, `올해 − 출생연도 = 14`이면 "올해 생일이 지났나요?" 자기 신고로 판정 (답은 저장 안 함). 이 방식으로 충분한지.
8. **마케팅 수신 동의 (Q-02, P-NOTI-02)** — 동의·철회 결과 고지, 푸시 "(광고)" 표기와 수신 거부 안내, 2년마다 재확인 의무, 야간(21~08시) 기준. Phase 1은 야간 마케팅 푸시를 아예 보내지 않는 것으로 썼다.
9. **약관 개정 공지 기간 (05 문서 4.2)** — 시행 7일 전, 불리한 변경 30일 전으로 가정.
