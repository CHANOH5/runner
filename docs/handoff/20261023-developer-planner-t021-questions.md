# T-021 구현 중 확인 질문 3건 (홈 다음 대회, 페이스 전략 재계산, 탈퇴 통계)

- From: developer
- To: planner
- 종류: 질문
- 관련 ID: S-010, S-033, F-021, F-072, PRD 6.7·6.17·4.15
- 상태: 답변됨

## 내용

T-021(앱 남은 API)을 구현하면서 PRD 문구대로 처리했지만, 화면에서 어색할 수 있는 3곳을 확인하고 싶다. 바꾸게 되면 서버 조건 한 줄이다.

1. **홈 "내 다음 대회"에 `접수 못 함` 대회도 나온다 (PRD 6.7 ②)**
   - 지금 규칙: "대회일 ≥ 오늘인 참가 예정 중 가장 빠른 것"이고, 접수 상태와 무관하다.
   - 그래서 `접수 못 함`으로 바꾸고 해제하지 않은 대회가 홈 첫 카드에 D-day와 함께 나올 수 있다. "외 n개"에도 포함된다.
   - 제안: `missed`는 내 다음 대회와 "외 n개"에서 빼고, S-061 참가 예정 탭에서만 회색으로 보이게 하기.
2. **페이스 전략(S-033)을 참가 예정 기준으로 열 때, 그 뒤 기록이 바뀐 경우**
   - 지금: 이 참가 예정에 연결된 가장 최근 예측을 그대로 보여주고 `recordsChangedSince = true`로 알린다. 다시 계산하지 않는다 (S-030 "기록이 바뀌었어요 · 다시 예측"과 같은 방식).
   - 홈 [페이스 전략 보기]나 N-04에서 들어오면 오래된 예측이 보일 수 있다.
   - 제안: 그대로 두고, S-033에도 "기록이 바뀌었어요 · 다시 예측" 링크를 표시하기 (앱 처리). 자동으로 다시 계산하면 사용자가 보던 숫자가 말없이 바뀐다.
3. **탈퇴 사유를 고르지 않은 탈퇴**
   - 지금: `account_deletion_stats`에 사유 없음(null) 행을 남긴다. 날짜만 있고 사용자 정보는 없다. 사유별 비율의 분모(전체 탈퇴 수)로 쓰려는 것이다.
   - 사유를 고른 탈퇴만 남겨야 하면 알려 달라.

## 기대하는 결과물 / 답변 형식
번호별로 "지금대로" 또는 바꿀 규칙.

## 답변 (받는 쪽이 작성)

(planner, 2026-10-23 — PRD v1.9 반영)
1. **바꾼다 (제안대로).** `entry_status = missed`인 참가 예정은 홈 "내 다음 대회" 카드와 "외 n개" 개수에서 뺀다. `missed`만 남아 있으면 빈 상태(`next: null`). S-061 참가 예정 탭에서는 지금처럼 회색으로 보인다. S-060 숫자 카드 "참가 예정 n"은 S-061 탭과 같은 기준(missed 포함)으로 둔다. PRD 6.7 ②, 와이어프레임 S-010·S-061. **서버 변경: `GET /home/next-race`의 대상 조건에 `entry_status <> 'missed'` 추가** (응답 스키마 변경 없음).
2. **지금대로 + 앱 안내 추가 (제안대로).** 자동으로 다시 계산하지 않고 저장된 최신 예측을 보여준다. `recordsChangedSince = true`면 S-033 결과 카드 위에 "기록이 바뀌었어요 · 다시 예측"을 표시하고, 탭하면 S-032를 같은 목표(참가 예정이면 그 참가 예정)로 연다. 다시 예측해 저장하면 그 참가 예정의 최신 예측이 된다. PRD 6.17, 와이어프레임 S-033. **API 변경 없음** (`GET /registrations/{id}/strategy` 응답의 `prediction.recordsChangedSince`가 채워져 있는지만 확인해 달라).
3. **지금대로.** 사유를 고르지 않은 탈퇴도 "사유 없음"(null) 1건으로 남긴다 (날짜만, 사용자 정보 없음). 전체 탈퇴 수 분모로 쓴다. 기타 자유 입력은 개인정보가 들어갈 수 있으니 관리자 화면에 보여줄 때는 날짜 단위 묶음으로만. PRD 4.15 명시. **API 변경 없음.**
