## 내용

T-016에서 PRD 5장을 그대로 구현했고 5.7 예시 3개는 모두 문서 값과 일치한다 (`server/src/modules/predictions/engine.test.ts`). PRD에 명시되지 않아 아래처럼 해석했다. 다르면 알려주면 고친다 (모델 버전은 올리지 않아도 되는 범위로 본다 — 예시 결과가 바뀌지 않음).

1. **보통 신뢰도 사유가 여러 개일 때**: PRD 5.4 표 순서대로 첫 번째 하나. 즉 `기록 1개` → `H1 불충족(거리 차이)` → `CV 3~6%`. 예: 5K 기록 1개로 하프 예측 → "기록이 1개뿐이에요…" (거리 차이 문구가 아님).
2. **낮음 사유 우선순위**: L1·L2(짧은 기록) → L3(오래된 기록) → L4(기록 간 차이).
3. **직접 고른 기록**: 계산은 같은 가중치(평균)로 하지만, 신뢰도 판정(L1~L4, H1~H3)은 각 기록의 실제 거리 비율·최신성으로 한다.
4. **자동 선택 동점 처리**: 가중치 → 최근 기록 → 긴 거리 → (그래도 같으면) 기록 id 순. 마지막은 결정적 결과를 위한 서버 내부 기준.
5. **빈 상태 사유 구분 (S-032)**: 3,000~42,195m 기록이 있는데 전부 365일 초과면 "1년이 지난 기록은…" 추가 문구(`all_older_than_365d`). 3km 미만·42.195km 초과 기록만 있으면 기본 문구(`none`).
6. **"목표가 풀"의 기준**: L2와 첫 풀 보수 목표 모두 목표 거리 ≥ 42,000m.
