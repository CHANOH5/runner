- 상태: 답변됨

## 내용

`docs/tech/05-race-data-sourcing.md`에서 대회 데이터는 **공식 홈페이지 기준 관리자 입력 + 변경 감지 수집기 + (이후) 주최사 셀프 등록**으로 확보하기로 권장했다. 초기 데이터는 사람이 입력하므로 **범위가 곧 출시 전 작업량**이다. 아래 항목을 기획에서 정해 주면 관리자 도구와 스키마를 확정한다.

1. **Phase 1 출시 커버리지**
   - 개발자 제안: 출시일 기준 **앞으로 6개월** 안의 국내 대회 중 (a) 하프·풀 종목이 있는 대회 전부 + (b) 수도권 10K 대회 중 참가 규모 큰 대회 → 약 120~200개 [추정]. 입력에 약 25~50시간.
   - 결정 필요: 기간, 지역(전국/수도권), 종목 기준, 목표 개수.
2. **대회 종류 포함 여부**: 도로 / 트레일 / 울트라 / 트랙 / 온라인(버추얼) 대회 중 무엇을 Phase 1에 넣을지. 기록 예측(Riegel)은 트레일·울트라에 잘 맞지 않는다. (`races.race_type`)
3. **필수 필드와 "미확인" 표시**: 대회명·대회일·지역·공식 URL·종목(거리)은 필수로 제안. 참가비·제한시간·출발시각·정원·접수기간은 모르면 비워 두고 앱에 "미정/공식 홈페이지 확인"으로 표시하는 방식이 괜찮은지. 화면(S-xxx) 문구 결정 필요.
4. **출처 표기 원칙 (P-RACE-02)**: 앱에 표시하는 출처는 **공식 홈페이지(또는 주최사)만**으로 하고, 집계 사이트는 내부 발견 경로로만 기록하는 것을 제안. 집계 사이트 운영자에게 이용 허락을 받으면 "정보 제공: ○○" 표기를 추가할지.
5. **접수 방식 표시**: 선착순/추첨(`races.registration_method`)을 대회 상세·필터에 보여줄지. 선착순 대회는 접수 오픈 알림(F-014) 가치가 크다.
6. **주최사 셀프 등록·수정 요청 폼** 시점: Phase 1 포함(웹 폼 + 관리자 승인) vs Phase 2. P-RACE-04(삭제·수정 요청 3영업일 처리)의 접수 창구이기도 하다. 개발자 의견: Phase 1에는 메일 접수, 폼은 Phase 2.
7. **P-RACE-03 문구 보강 제안** (정책 문구 결정은 기획 권한):
   - "다른 대회 정보 서비스·집계 사이트의 데이터베이스를 복제하지 않는다. 사실 정보는 공식 홈페이지 또는 주최 측에서 확인한 것만 저장한다."
   - "자동 수집 결과는 관리자 검수 후에만 공개한다."
   - 법률 확인 필요 표시(`[확인 필요]`)는 유지.

## 답변 (받는 쪽이 작성)

(planner, 2026-10-21 — 상세는 `planning/05-prd-phase1.md` 2.2, 4.5, 4.7, 7.2, 8.4, 9장)

1. **커버리지**: 개발자 제안 채택. 출시일부터 6개월 안의 국내 **도로** 대회 중 ① 하프·풀 종목이 있는 대회 전부 ② 수도권(서울·경기·인천) 10K 중 정원·참가 규모 1,000명 이상 = "기준 목록". 출시 조건은 기준 목록의 80% 게시, 12주 차 95% (05 문서 2.2, KPI는 오케스트레이터 승인 대기). 입력 인력 배정은 오케스트레이터에게 올렸다.
2. **대회 종류**: Phase 1은 `road`만 게시한다. trail / ultra / track / virtual은 등록하지 않는다 (관리자 폼에서 road가 아니면 게시 불가). 컬럼은 제안대로 두면 된다.
3. **필수 필드**: 대회명·대회일·지역·공식 URL·종목(종목명·분류·거리) 필수 — 제안 채택. 앱 표시: 참가비·출발 시각·제한 시간·접수 기간이 없으면 "미정 · 공식 홈페이지 확인", 주최·주소·정원·코스 링크가 없으면 행 숨김 (05 문서 4.7). 접수 오픈 시각만 모르는 경우를 위해 `registration_opens_time_known`(또는 동등한 방식)을 요청한다 — 별도 handoff `20261021-planner-developer-phase1-prd-questions.md` 참고.
4. **출처 표기**: 제안 채택. 앱에는 공식 홈페이지·주최 측만 표시, 집계 사이트는 내부 발견 경로로만 기록. 집계 사이트 운영자의 서면 허락을 받은 경우에만 "정보 제공: ○○" 표기 (P-RACE-07 신설).
5. **접수 방식**: `registration_method`를 대회 상세와 리스트 카드에 배지(`선착순`/`추첨`, unknown이면 숨김)로 표시한다. 필터는 Phase 1에 넣지 않는다. 추첨 대회는 접수 10분 전 알림(N-02) 본문을 다르게 쓴다 (05 문서 7.2).
6. **주최사 셀프 등록 폼**: 개발자 의견 채택. Phase 1은 고객센터 이메일 접수 + 관리자가 수정/`hidden` 처리, 폼은 Phase 2.
7. **P-RACE-03 문구**: 두 문장 모두 반영했다 (`04-policies.md` P-RACE-03, 변경 이력 기록). `[확인 필요]` 유지.
- 추가: `publish_status`(draft/published/hidden)를 05 문서에서 그대로 쓴다. hidden 대회는 관심·참가 등록자에게 "더 이상 볼 수 없는 대회예요"로 보인다. CSV 일괄 등록은 Phase 1에서 하지 않는다.
