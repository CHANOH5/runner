## 내용

D-019에 따라 용어 후보를 비교해 **"참가 예정"** 을 제안하고, 기획 문서(01~05)와 와이어프레임에 이미 반영했다 (PRD v1.4 4.10 "용어 선택 근거").

| 후보 | 판단 | 이유 |
|---|---|---|
| **참가 예정** | **채택 제안** | 일상어이고 의도만 표시한다 ("접수"를 연상시키지 않음). 이미 S-060·S-061의 탭 이름이라 화면 간 일관된다. "참가 예정 · 접수 전"처럼 접수 상태와 붙여 읽기 자연스럽다 |
| 나갈 대회 | 보류 | 친근하지만 명사구라 버튼·상태 문구로 어색하다 ("나갈 대회 해제"). 마케팅 문구로는 쓸 수 있다 |
| 출전 예정 | 미채택 | "출전"은 선수·엘리트 느낌이라 핵심 페르소나(첫 하프 도전자)와 거리가 있다 |

### 1. 결정 요청
- "참가 예정" 용어를 `decisions.md` D-019에 확정으로 기록해 달라 (D-019는 "기획자 제안 후 확정"으로 되어 있음).

### 2. `CLAUDE.md` 5장 용어표 수정 문구 (오케스트레이터 파일이라 직접 고치지 않았다)
현재:
```
| 참가 등록 | 사용자가 앱에서 "이 대회 종목에 나간다"고 표시하는 것 (실제 접수는 외부) |
```
변경안 (행 교체 1개 + 행 추가 1개):
```
| 참가 예정 | 사용자가 앱에서 "이 대회 종목에 나간다"고 표시하는 것. **실제 접수가 아니다** (접수는 공식 홈페이지에서만, P-RACE-01). 구 "참가 등록" — 화면 문구에 쓰지 않는다 |
| 접수 상태 | 참가 예정한 대회의 공식 접수 여부를 사용자가 직접 기록한 값: 접수 전 / 접수 완료 / 접수 못 함 (자기 기록, 참가 인증 아님, P-RACE-08) |
```
- 같은 표의 "참가 인증" 행은 그대로 둔다.

### 4. 참고 — 기획에서 정한 것
- 접수 상태 3개 (접수 전 / 접수 완료 / 접수 못 함), 공식 링크 복귀 질문 (10초 이상 체류, [아직이에요]·무시 시 24시간 안 묻지 않음, 누적 3회면 그 대회는 중단), 마감 알림 N-03은 접수 전만, N-04·N-05는 접수 못 함 제외 (PRD 4.10.1, 7.2).
- KPI 추가 `[가설]`: 접수 완료 기록률 ≥ 30%, 접수 상태 응답률 ≥ 50%, 접수 상태 확정률 ≥ 60% (PRD 2.1).
- 정책 P-RACE-01 보강, P-RACE-08 신설 (접수 상태는 자기 기록, 인증에 쓰지 않음).
