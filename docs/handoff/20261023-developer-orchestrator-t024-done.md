## 내용

브랜치 `claude/admin-web`(main `579fcc7` 기준)에 T-024를 끝냈다. push·main 병합은 하지 않았다. 사용자 승인 후 병합해 달라.

**구현한 것**
1. 새 워크스페이스 `admin/`
   - Next.js 15 (App Router) + React 19 + TypeScript
   - 루트 `pnpm lint`·`typecheck`·`build`·`test`와 CI에 포함된다.
2. 화면
   - A-001 로그인: 비밀번호 → TOTP → 세션
   - A-002 대시보드: 대회·제보 수만 보인다. 기존 목록 API로 센다. 사용자·알림·입력 진행·이번 주 접수 오픈은 "준비 중"이다.
   - A-003 대회 목록·등록·수정: PRD 8.4 빠른 입력, 게시·게시 취소·숨김·삭제, 입력 중 중복 경고, 게시 대회의 취소·연기·일정 변경 때 영향 수 모달(+ 변경 알림 선택)
   - A-004 제보 목록·상세: 일괄 반영·반려, 사유 템플릿, 같은 항목 제보 함께 처리
   - A-008: API가 없어 자리만 있다.
3. API 연결
   - 같은 출처 `/api/admin/*`로 부른다. 로컬은 Next.js rewrites가 처리한다. 세션 쿠키·CSRF는 그대로다.
   - 에러 코드는 한국어 문구로 바꾼다. 입력 검증은 공유 Zod 스키마를 쓴다.
4. 서버 변경 (작음)
   - `GET /auth/me`가 `csrfToken`을 함께 준다 (`no-store`). 새로고침 후 CSRF를 복구하는 데 쓴다.
   - 개발용 관리자 시드와 TOTP 스크립트는 `NODE_ENV=production`이면 거부한다 (테스트 추가).
5. 로컬 실행
   - `pnpm dev:admin` → API :3000 + 관리자 웹 http://localhost:3100
   - 개발용 로그인 방법은 README "관리자 웹 (T-024)"에 있다. 2단계 코드는 `pnpm dev:admin-totp`로 얻는다.

**확인**
- 실제로 띄워 브라우저에서 확인했다:
  - 로그인 (비밀번호 → TOTP)
  - 새 대회 등록 (빠른 날짜·시각, 하프+풀 프리셋, 공통값 적용) → 게시
  - 복제 → 게시 시도(422 누락 항목 표시) → 확인 체크 → 게시 → 게시 취소 → 삭제
  - 제보 상세 → 반영 완료
- 테스트: 관리자 웹 9개(로그인·대회 저장·게시 422→성공·충돌 에러, 빠른 입력 해석)와 서버 229개가 통과했다. Node 22에서도 build·test를 확인했다.
