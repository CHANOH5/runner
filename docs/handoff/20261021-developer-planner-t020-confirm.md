# T-020 구현 중 해석한 규칙 확인 3건

- From: developer
- To: planner
- 종류: 질문 (확인)
- 관련 ID: N-02, S-011, A-003, PRD 7.1·8.4.2
- 상태: 답변됨

## 내용

PRD v1.7을 반영하면서 문서에 없는 경우를 아래처럼 처리했다. 다르면 알려 달라. 모두 서버 한두 줄 변경이다.

1. **N-02 묶음에 오픈 시각 미정 대회가 섞인 경우**
   - 예: 09:10 오픈 대회(−10분 = 09:00)와 시각 미정 대회(오픈일 09:00)가 같은 시각에 묶이는 경우다.
   - "10분 뒤 접수가 열리는"은 미정 대회에는 틀린 말이라, 하나라도 섞이면 **"오늘 접수가 시작되는 대회 {n}개"** 로 보낸다.
2. **알림 목록(S-011)의 시각**
   - "3시간 전" 표시와 정렬에 **알림을 보내기로 한 시각**(예: N-01이면 전날 19:00)을 쓴다.
   - 대상 확정 때문에 서버에 행이 30분 먼저 생기므로, 생성 시각을 쓰면 실제로 받은 시각과 30분 어긋난다.
   - 90일 보관 기준은 생성 시각 그대로다.
3. **게시된 대회의 대회 종류 변경**
   - PRD 8.4.2: 도로 외 종류는 "저장은 되지만 게시 불가"다.
   - 이미 게시된 대회를 트레일 등으로 바꾸는 저장은 **막았다** (400). 저장을 허용하면 게시 조건을 어긴 대회가 앱에 계속 보이기 때문이다.
   - 바꾸려면 먼저 숨김 또는 게시 취소를 해야 한다.

## 기대하는 결과물 / 답변 형식
번호별로 "맞음" 또는 바꿀 규칙.

## 답변 (받는 쪽이 작성)

(planner, 2026-10-23 — PRD v1.8 반영, 3건 모두 구현대로)
1. **맞음.** 오픈 시각 미정 대회가 하나라도 섞인 N-02 묶음은 "오늘 접수가 시작되는 대회 {n}개". PRD 7.2 묶음 제목 표에 명시.
2. **맞음.** S-011 상대 시각 표시와 정렬은 `scheduled_at`(보내기로 한 시각), 90일 보관·파기는 생성 시각 기준. 즉시 발송 알림은 두 값이 같다. PRD 6.8에 명시. (API 응답의 `createdAt` 대신 표시용 시각을 쓰는 것이라면 필드 이름이 헷갈리지 않게 `tech/06`에 한 줄 적어 두면 좋겠다 — 기획 요구는 위 기준뿐.)
3. **맞음.** 게시 중인 대회는 도로 외 종류로 저장할 수 없다 (400). 관리자 폼에서는 대회 종류 칸을 비활성으로 두고 "게시 중인 대회는 종류를 바꿀 수 없어요. 먼저 숨김 또는 게시 취소를 해주세요"를 보여준다. 게시 취소는 관심·참가 예정 0일 때만 되므로 참가자가 있으면 숨김 후 변경한다. PRD 8.4.2, 와이어프레임 A-003 반영. 400 응답의 fieldErrors code를 앱(관리자 웹)이 이 문구로 매핑할 수 있게 해 달라.
