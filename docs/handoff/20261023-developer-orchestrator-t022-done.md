## 내용

브랜치 `claude/dev-unlink-worker`(main `40d5143` 기준)에 T-022를 끝냈다. push·main 병합은 하지 않았다. 사용자 승인 후 병합해 달라.

**구현한 것**
1. `GET /home/next-race`에서 `missed`를 뺐다. 카드와 "외 n개" 모두에서 빠지고, missed만 남으면 `next: null`이다.
   - strategy의 `prediction.recordsChangedSince`가 기록 변경 전후로 false → true가 되는 것을 테스트로 보장했다.
2. 소셜 연결 해제 워커 (BullMQ `accounts` 큐, 알림 워커와 같은 프로세스)
   - 대상: 카카오 unlink, Apple revoke. Google은 제외한다.
   - 처리 순서: 재가입 확인 → provider 호출 → 결과 처리
   - 결과 분류: 성공·이미 해제됨은 삭제, 일시 실패는 백오프(1~60분, 24시간)로 재시도, 영구·기한 초과는 최종 실패로 식별자를 지우고 사유만 남긴다.
   - 7일 정리 배치를 매일 돌리고 `deletion_jobs`에 기록한다.
   - 로그: 식별자는 해시 앞 8자리, 토큰은 기록하지 않는다. pino redact도 추가했다.
   - 마이그레이션 `0006`
3. 테스트 218개 통과. 실제 provider 호출은 없다. 가짜 클라이언트로 검증했고, HTTP 응답 분류는 가짜 fetch로 검증했다.

**보드 갱신 요청**: T-022 → `검토` (또는 병합 후 `완료`).

**알아 둘 것**
- 운영에서 실제로 해제하려면 다음이 필요하다:
  - `UNLINK_DRY_RUN=false`
  - `KAKAO_ADMIN_KEY`
  - Apple 키 (`APPLE_*`)
  - `TOKEN_ENC_KEY` (Apple 토큰 복호화)
- 키가 없으면 일시 실패로 24시간 재시도한 뒤 최종 실패로 기록된다. 키를 발급하면 실제 계정 1개로 수동 확인이 필요하다.
- 최종 실패 기록은 식별자 없이 사유만 남는데, 그 행의 보관 기간은 정하지 않았다. 지금은 계속 둔다. 관리자 대시보드(A-002)에 실패 수로 보일 예정이다. 정리 주기가 필요하면 알려 달라.
- 식별자·Apple 토큰 최대 7일 보관은 decisions.md 미결 질문(법률 확인)에 이미 있다. 그대로 구현했다.
- 명세와 다르게 한 것 (tech/03·04 반영)
  - 설계는 "최종 실패 시 행 즉시 삭제"였다. "최종 실패를 기록한다"는 이번 요구에 맞춰, 행을 지우지 않고 식별자·토큰만 지운 실패 기록으로 남겼다.
  - 카카오 `-101`과 Apple `invalid_grant`는 "이미 해제됨"으로 보고 성공 처리한다.

**다음 작업 제안**
1. 관리자 나머지: 대시보드(A-002, 알림·연결 해제 실패 수 포함), 공지·마케팅(N-08, `GET /notices/{id}`), 원격 설정
2. `GET /races/count`, `GET /races/calendar`, 요청 제한(Redis), 멱등 키
3. 휴면 처리 배치(P-RET-03: 1년 미접속 → 30일 전 안내 → dormant)
4. CI·배포 준비 (KMS, 첫 owner 시드, 키 주입)
