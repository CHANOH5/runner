# 휴면 안내 문구·"접속" 기준 확인

- From: developer

- 상태: 답변됨

## 내용

T-023 휴면 처리 배치에서 PRD에 없는 두 가지를 아래처럼 정했다. 맞는지, 바꿀 문구가 있는지 알려 달라.

1. **안내 푸시·앱 내 알림 문구 (초안)**
   - 제목: "휴면 계정 전환 안내"
   - 본문: "{M월 D일}에 휴면 계정으로 바뀌어요. 그 전에 앱을 열면 계속 쓸 수 있어요."
   - 탭 이동: S-011
   - 발송 시각: 매일 10:00 배치 (새벽 발송을 피함). 알림 설정과 무관하게 보낸다 (고지 성격).
   - 알림 종류 `dormancy_notice`를 앱 알림 목록 아이콘·문구 매핑에 추가해야 한다.
2. **"로그인하지 않은"의 기준 = 마지막 "접속"**
   - P-RET-03은 "1년 이상 로그인하지 않은"이다. 그런데 앱은 refresh token으로 로그인을 유지하므로, 소셜 로그인만 세면 매일 쓰는 사용자도 1년 뒤 휴면이 된다.
   - 그래서 **앱을 열 때의 토큰 회전도 접속으로** 세었다. 기준은 소셜 로그인·가입·토큰 회전 중 마지막이다.
   - 1년간 앱을 한 번도 열지 않은 사람만 휴면 대상이 된다.
   - 정책 문구를 "1년 이상 접속(앱 사용)하지 않은"으로 맞춰 주면 좋겠다.

참고로 안내 없이 휴면으로 만들지 않는다. 안내가 늦으면(배치 장애 등) 휴면도 안내 후 30일 뒤로 미룬다.

1. **규칙은 맞음, 제목만 수정.** 알림 번호는 **N-09** (`dormancy_notice`).
   - 제목: **"{닉네임}님, 계정이 곧 휴면으로 바뀌어요"** (고정 18자 + 닉네임 최대 12자 = 30자, 줄임 불필요)
   - 본문: "{M월 D일}에 휴면 계정으로 바뀌어요. 그 전에 앱을 열면 그대로 쓸 수 있어요." ("계속" → "그대로"만 바꿈)
   - 발송: 매일 10:00 배치, 알림 설정과 무관(마케팅 아님, 고지 성격), 휴면 주기마다 1회, 묶음 없음. OS 권한이 꺼져 있으면 앱 내 알림만.
   - 탭 이동: S-011 (지금대로). 앱을 여는 것 자체가 접속이라 휴면 전환은 취소된다.

   - 안내 지연 시 휴면 전환일을 "안내 + 30일"로 미루는 처리는 그대로 맞음 (PRD 4.1에 명시).
   - 이메일 안내는 D-021에 따라 보류 (PRD 4.1, 7.2, P-RET-03에 명시).
