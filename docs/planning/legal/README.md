### "개인정보 수집·이용 동의"(`privacy`)와 "개인정보 처리방침"의 차이
- **수집·이용 동의**: 가입 시 받는 **필수 동의**. 짧은 요약 문서 — 수집 항목, 목적, 보유 기간 3가지만 표로 (PRD 6.3의 S-003 요약 표와 같은 내용). `privacy-policy.md` 1·3장에서 Phase 1 필수 항목만 뽑아 만든다 → **다음 작업** `[미정]`.
- **처리방침**: 동의 대상이 아닌 **게시 문서** (전체 내용).
- 둘 다 `privacy`라는 이름을 쓰지만 다른 문서다. 앱 문구: "개인정보 수집·이용 동의 [보기]" (필수 체크) / "개인정보 처리방침 보기" (링크만).
- 개인정보 보호법 개정으로 "필수 동의" 방식 자체가 바뀌었는지(계약 이행에 필요한 정보는 동의 없이 처리 가능) `[확인 필요]` — 바뀌었다면 필수 `privacy` 동의를 없애고 처리방침 고지만 할 수 있다.

## 2. 버전·시행일 운영 규칙
- 버전 표기: 초안 `v0.x` → 법률 검토 후 게시본 `v1.0` → 개정 시 `v1.1`, `v2.0`(중요 변경).
- 게시 시 `terms_versions`에 `(kind, version, required, content_url, effective_at)` 1행 추가. 같은 kind의 새 버전이 `effective_at`에 도달하면 앱이 재동의 화면을 띄운다 (PRD 4.2, 필수 약관만).
- 처리방침은 동의가 없으므로 `privacyPolicyUrl` 주소의 내용을 바꾸고, 시행 7일 전(중요 변경 30일 전) A-008 공지를 보낸다.
- 공지 기간(약관 7일·불리한 변경 30일)은 `[확인 필요]`.
- 각 문서 하단 "변경 이력"과 이 README 표를 같이 고친다.

## 3. 게시 위치 `[미정]`
- 약관 `content_url`과 `privacyPolicyUrl`은 앱 밖 웹 주소다. 도메인(Q-12)이 정해지기 전에는 임시 주소에 정적 페이지로 올린다. 호스팅 방식은 개발자에게 요청했다 (handoff `20261027-planner-developer-legal-docs.md`).
- 앱은 웹뷰로 연다 (PRD 4.2).
